# AI Radar — AI 实时资讯雷达

一个 Windows 桌面应用，持续聚合 **14 个** AI 相关数据源（论文 / 国内资讯 / 海外资讯 / 社区热议 / 开源项目），
有新内容时推送系统通知，支持分类筛选、关键词关注、搜索、已读与收藏。

界面为深色主题，自绘标题栏，常驻系统托盘。

---

## 一、快速开始

### 方式 A：直接运行打包好的程序（推荐）

双击 `dist/AI Radar Setup 1.0.0.exe` 安装，或直接运行免安装版：

```
dist/AI-Radar-1.0.0-portable.exe
```

### 方式 B：从源码运行

```bash
# 一次性初始化（安装依赖 + 拉取 Electron 二进制 + 生成图标）
npm run setup

# 启动
npm start
```

> **关于 `npm run setup`**：本项目的安装脚本用 `--ignore-scripts` 跳过了 npm 的 postinstall，
> 改由 `node scripts/fetch-electron.mjs` 手动下载 Electron 二进制。
> 这样做是因为 Electron 的 postinstall 需要 spawn 子进程，在受限环境下会以 `EPERM` 失败；
> 手动下载同样走国内镜像（npmmirror），更稳且可重复。

## 二、功能说明

| 功能 | 说明 |
|---|---|
| **自动刷新** | 默认每 5 分钟抓取一次，可在 1 分钟 ~ 1 小时之间调整 |
| **系统通知** | 发现新内容时推送 Windows 通知，点击直接跳转到该条；可按「重要度阈值」控制打扰频率 |
| **分类筛选** | 论文 / 国内资讯 / 海外资讯 / 社区热议 / 开源项目，侧栏显示各类数量 |
| **数据源开关** | 逐个启用或停用数据源，状态面板显示每个源的抓取结果与耗时 |
| **关键词关注** | 自定义关注词（如 `DeepSeek`、`Agent`），命中的标题会高亮，并提升通知优先级 |
| **搜索** | 支持多关键词（空格分隔，需全部命中），按 `Ctrl+F` 快速聚焦 |
| **摘要与正文** | 点击卡片展开全文，自动把 RSS 的 HTML 清洗成可读纯文本 |
| **已读 / 未读** | 展开即标记已读；可筛选只看未读、一键全部已读 |
| **收藏** | 收藏内容本地留存快照，即使原文失效仍可回看 |
| **托盘常驻** | 关闭窗口默认最小化到托盘而不退出；托盘菜单可直接刷新、开关自启、退出 |
| **开机自启** | 可设置为开机静默启动到托盘 |
| **离线可用** | 最近一次结果会缓存，断网启动也能立刻看到上次内容 |

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `F5` / `Ctrl+R` | 立即刷新 |
| `Ctrl+F` | 聚焦搜索框 |
| `Ctrl+D` | 切换深色 / 浅色主题 |
| `Ctrl+,` | 打开设置 |
| `Esc` | 关闭设置面板 / 清空搜索 |

### 已知不可用的源（已排除，非缺陷）

| 源 | 原因 |
|---|---|
| arXiv | `export.arxiv.org` / `arxiv.org` 在本机请求全部超时 |
| 36氪、机器之心 | RSS 地址已失效，返回 HTML 页面 |
| Reddit、Google News | 请求超时 |
| HuggingFace 主站 | 直连失败，已用 `hf-mirror.com` 镜像替代 |

### 网络容错设计

- 每个源独立超时（默认 20 秒，可按源覆盖），单源失败不影响其它源；
- 对网络类抖动自动重试 1~2 次（HTTP 4xx 这类确定性错误不重试）；
- 全局并发上限 6，避免同时打开过多连接被限速；
- 失败的源会在侧栏标红点，并在设置 → 数据源状态里给出具体原因。

### 两个反直觉的请求头细节

实测发现部分源会按 `User-Agent` 做反爬判断，而且行为与直觉相反：

- **量子位** 与 **MarkTechPost** 都会**拒绝完整的浏览器 UA**（返回 403），只接受最简 UA / 工具型 UA。

因此本项目**不做 UA 伪装去骗过风控**，而是按源声明其实际接受的请求头（见 `src/main/sources.js` 的 `HEADERS`）。
若某个源将来变更策略，只需在源定义里调整 `headers` 字段。

## 四、项目结构

```
project/
├─ package.json               # 依赖与 electron-builder 打包配置
├─ src/
│  ├─ main/                   # 主进程（Node 环境，负责网络与系统能力）
│  │  ├─ main.js              # 入口：窗口、托盘、通知、IPC、开机自启
│  │  ├─ scheduler.js         # 刷新调度：定时抓取、新内容判定、通知打分
│  │  ├─ aggregator.js        # 网络层：并发抓取、超时、去重、排序
│  │  ├─ parser.js            # 零依赖 RSS 2.0 / Atom 1.0 解析 + HTML 清洗
│  │  ├─ sources.js           # 数据源目录与 AI 关键词表
│  │  ├─ store.js             # 本地持久化（配置 / 已读收藏 / 缓存）
│  │  └─ smoke.js             # 冒烟测试支持（截图 + 诊断报告）
│  ├─ preload/preload.js      # 安全桥接（contextIsolation，白名单 API）
│  └─ renderer/               # 渲染进程（无 Node 权限）
│     ├─ index.html           # 界面骨架（含 CSP）
│     ├─ styles.css           # 深色 / 浅色主题
│     ├─ renderer.js          # 筛选、搜索、渲染、交互
│     └─ assets/              # 应用与托盘图标
├─ scripts/
│  ├─ fetch-electron.mjs      # 手动下载 Electron 二进制（走国内镜像）
│  ├─ make-icons.js           # 零依赖生成 PNG 图标
│  ├─ png.js                  # PNG 编码器
│  └─ smoke-test.js           # 启动应用并采集截图与报告
└─ test/run-tests.mjs         # 单元测试 + 真实数据源实测
```

### 架构要点

- **网络全部在主进程**：渲染进程开启 `contextIsolation` + `sandbox`、无 Node 权限。
  这样既绕开了渲染进程的 CORS 限制，也把外部内容与界面隔离开。
- **渲染进程只通过 preload 白名单通信**，不暴露任何文件系统或命令执行接口。
- **CSP 禁止远程脚本**，外部链接一律交给系统浏览器打开（`http/https` 之外一律拒绝）。
- **卡片按 id 复用 DOM 节点**，刷新时只增删差异，因此滚动位置与展开状态不会被打断。
- **所有跨进程数据都过一遍解析器**，单个脏条目不会拖垮整批抓取。

## 五、开发与测试

```bash
npm test              # 离线单元测试（解析器 / 去重 / 摘要识别 / 配置存储）
npm run test:live     # 额外实测全部 14 个真实数据源
npm run smoke         # 启动应用，抓取完成后自动截图 + 输出诊断报告到 .smoke/
npm start             # 正常运行
npm run dev           # 带控制台日志运行
npm run build         # 打包出 Windows 安装包与免安装版
```

`npm run test:live` 会逐个打印每个源的抓取条数与耗时，便于快速发现某个源失效。

`npm run smoke` 会生成 `.smoke/report.json`，内含：页面是否加载、JS 报错、各源抓取结果、
实际渲染出的卡片数量、布局关键元素尺寸、以及交互功能的逐项校验结果。

## 六、数据存放位置

应用数据保存在 Electron 的 `userData` 目录（设置面板内可一键打开）：

```
%APPDATA%\AI Radar\
├─ config.json    # 刷新间隔、通知开关、关注关键词、启用的源
├─ state.json     # 已读 id 列表、收藏内容快照
└─ cache.json     # 最近一次抓取结果（离线启动用）
```

写入采用「先写临时文件再原子重命名」，避免崩溃留下半截 JSON；
若文件损坏会自动备份为 `.corrupt` 并回退默认值，不会阻塞启动。

## 七、常见问题

**Q：列表里某些卡片没有摘要，显示"该源仅提供标题"？**
A：这是数据源本身不提供摘要。例如 InfoQ 中文的 RSS 只给了一个"点击查看原文"的导航链接，
正文需要登录才能看。应用会识别并丢弃这类无信息量的占位文本，而不是把它当摘要显示。

**Q：某个源抓取失败了？**
A：打开设置 → 数据源状态，可以看到每个源的成败与错误原因。
网络受限、源站改版、临时限流都可能导致失败，应用会自动跳过失败源、不影响其它源。
也可以在源列表里直接停用该源。

**Q：为什么 arXiv 没有？**
A：本机对 `export.arxiv.org` 与 `arxiv.org` 的请求全部超时（网络受限）。
替代方案是 HuggingFace 每日论文，它本身就是 arXiv 论文的精选聚合。

**Q：通知太频繁 / 完全不想被打扰？**
A：设置 → 抓取与通知：关闭通知开关，或把「通知重要度阈值」调高。
每次刷新的通知上限为 3 条，且首次启动不发通知。

**Q：关闭窗口后程序还在？**
A：这是托盘常驻设计。右键托盘图标可退出，或在设置里关闭「关闭窗口时最小化到托盘」。
